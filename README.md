# Crisis Engine v4.0 · Magic Box

**Назначение:** независимый монитор экономических фактов и неоптимизированных гипотез о финансовом риске. НЕ инвестиционный совет, не прогноз вероятности падения рынка.

## Установка

1. В репозитории `limonfree/crisis` замените файлы `engine.py`, `collect.py`, `index.html`, `.github/workflows/update.yml`, файлы в `tests/`.
2. **Добавьте** новые файлы `v4.py`, `evaluate.py` и документы `README.md`, `METHODOLOGY.md`.
3. Загрузите всё из ZIP с правильной структурой папок. Старые `data/latest.json`, `data/history.json`, `data/source_cache.json` **не удаляйте**.
4. В GitHub откройте `Actions → update-data → Run workflow`, дождитесь успешного запуска. Для записи нужен `Settings → Actions → General → Workflow permissions → Read and write permissions` либо права через предоставленные `permissions: contents: write` (при организационных ограничениях этого может быть недостаточно).
5. Проверьте `data/latest.json` (`schema:4`, `model_version:4.0.0`), `data/signal_log.json`, `data/evaluation.json` и каталог `data/snapshots/YYYY/MM/`.
6. Откройте GitHub Pages: `https://limonfree.github.io/crisis/`.

Сборщик запускается каждые 3 часа, **первый удачный запуск каждого UTC-дня** создаёт отдельный неизменяемый в логике приложения снимок. Повторные запуски дня продолжают обновлять `latest.json`, но **не перезаписывают архивный снимок**. Git-история фиксирует любые изменения после коммита. Для исторических источников все серии отдельно сохраняются в `data/vintages/YYYY/MM/YYYY-MM-DD.json.gz` (сжатый JSON). Место на диске GitHub со временем будет увеличиваться; следите за размером репозитория.

## Что появилось в v4

- Четыре раздельные диагностические модели: `market`, `credit_liquidity`, `macro`, `crypto`.
- HY OAS уровень и динамика считаются **одной**, а не двумя независимыми кредитными группами.
- Оценки по активам v3 больше **не превращаются в торговые сигналы**; исходный комбинированный стресс-индекс доступен только справочно.
- Массив опубликованных ежедневных моделей: `data/signal_log.json` (при необходимости последние 365 дней в UI), архив первых запусков UTC-дня: `data/snapshots/...`.
- Записанные значения первичных рядов и времена сбора: `data/vintages/...json.gz`. Это **снимки реально собранной информации**, но не подтверждённые исторические официальные даты релизов ALFRED.
- `data/evaluation.json` проверяет фактически заархивированные предупреждения на горизонте **5/20/60 следующих наблюдавшихся закрытий** SPY/BTC/ETH; там нет задним числом сгенерированных сигналов.
- Внутридневные цены не используются: оценка закрытия берётся с даты **до** UTC-даты сохранения. Пропуски наблюдений цензурируются.
- Публикация частот событий запрещена до **30 завершённых независимых эпизодов**. Даже после этого это историческая частота, **не калиброванный прогноз**.
- Показан тест чувствительности порогов на **количество срабатываний в реально записанные дни**, но он НЕ оптимизирует прибыльность.
- Раскрываемый справочник простыми словами, ссылки на источники, даты наблюдений; главная страница на чистом HTML/CSS/JS без фреймворков.

## Важные пределы

1. Нельзя считать снимки v4 до первого запуска — они **не восстанавливаются задним числом** из пересмотренных данных v3.
2. FRED, DBnomics, Yahoo Finance и прочие источники могут ошибаться или менять прошлые значения. Даты доступности прошлых выпусков в ядре являются приблизительными — для полноценного макро-PIT-бэктеста нужно ALFRED и официальные архивы выпусков.
3. Цена SPY используется **без дивидендов**, а котировки Yahoo могут быть позднее пересмотрены вследствие сплитов. Результаты Strategy Lab пока **без комиссий и проскальзывания**.
4. Сессии — не строго биржевые дни по расписанию: это последовательно зафиксированные закрытия. При провалах ежедневного мониторинга эпизод исключается, а не домысливается.
5. Пороги сделаны прозрачными, но пока **не калиброваны**. Нет обучающей/тестовой выборки, контрольной группы, доказанных торговых правил входа/выхода, или математически обоснованных вероятностей.
6. Показатель `coverage` измеряет число доступных рядов, а не точность вывода.
7. `Обновить` перечитывает уже опубликованные файлы, а не запускает GitHub Actions. Для нового забора данных нужен запуск сборщика.

## Проверка в локальном Python 3.12

```bash
python -m compileall -q engine.py collect.py v4.py evaluate.py tests
python -m unittest discover -s tests -v
```

В папке `tests` нет искусственного `data/latest.json`, тесты создают временное окружение. Для нового полноценного сбора с интернетом необходим запуск GitHub Actions.
