# CRISIS ENGINE v3.4 · Magic Box

Лёгкая страница для понимания финансовой напряжённости без платных графиков и фронтенд-библиотек.

## Установка на GitHub Pages

1. На ветке `main` репозитория `limonfree/crisis` **замените** `engine.py`, `collect.py`, `index.html`.
2. **Замените** `.github/workflows/update.yml` (важен каталог `.github/workflows/`).
3. **Добавьте** папку `tests/` с `test_calendar.py` и `test_integration.py`.
4. Проверьте, что GitHub Pages настроен на публикацию из корня ветки `main`.
5. Откройте **Actions → update-data → Run workflow**. После успешного завершения проверьте адреса
   `https://limonfree.github.io/crisis/data/latest.json` и
   `https://limonfree.github.io/crisis/data/history.json`.
6. Обновите страницу с очисткой кэша. В заголовке должна появиться версия **v3.4**.

Никаких `pip install` не требуется: сборщик и тесты работают на стандартной библиотеке Python 3.12. Секрет GitHub Actions `FRED_API_KEY` необязателен. При его отсутствии используются DBnomics (копия рядов FRED) и FRED CSV.

Важно: «↻ Обновить» на странице перечитывает **уже опубликованные JSON**. Поскольку GitHub Pages — статический хостинг, начать новый Python-сбор в обход GitHub Actions кнопка не может. Кнопка «Новый сбор ↗» открывает GitHub Actions для ручного запуска пользователем с правами.

## Что исправлено в v3.4

- **CPI и core PCE YoY, M2 YoY, квартальные значения** сверяются с тем же **календарным месяцем**, а не с «12-й предыдущей записью». Если нужный месяц отсутствует, результат не подставляется.
- **Четыре / двенадцать недель** сравниваются с фактической датой −28 / −84 дней. Для биржевых/недельных рядов допустим небольшой известный разрыв из-за выходных; для месячных — **никакого** заимствования соседнего месяца.
- Пропуск базы сравнения не приводит к показу результата **прошлого месяца** как текущего.
- Окна скорости спредов, M2, ликвидности и денежного баланса Банка Японии приведены к времени, указанному в названиях.
- **Risk-off** требует подтверждения биржевой динамикой или VIX; одного значения Market Stress уже недостаточно. Условия в разделе «Переходы» берутся **из того же расчёта**, что и основная классификация.
- Сильные макросигналы спада определяются по **четырём** условиям, а не «3 из 5» при недоступном GDPNow. Это не официальное объявление рецессии.
- GDPNow доступен только **справочно** и исключён из итогового индекса/исторической классификации до появления верифицируемой истории реальных дат релизов.
- Выводы в интерфейсе разделены на **наблюдаемые данные**, **правила модели** и **ограничения**. Вместо призывов «покупать» и «продавать» выводятся уровни настороженности.
- Кнопка **«? Справочник»** и знак **?** рядом с каждым из 31 показателя дают короткое объяснение, способ чтения, ограничение и ссылку на источник.
- Выходной JSON сохраняет `schema: 3`, совместим с фронтендом. Добавлено поле `model_version: "3.4"`.

## Самопроверка

```bash
python -m unittest discover -s tests -v
python -m py_compile engine.py collect.py
```

Проверки запускаются **до сборки** в GitHub Actions. Для публикации нужны валидные `data/latest.json` и `data/history.json`. Если источников недостаточно, старая публикация сохраняется и workflow завершается ошибкой вместо подмены цифр.

## Границы достоверности — обязательно прочитать

- `Crisis Score` (0–100) — *авторский индекс стресса*, **не** вероятность финансового краха/рецессии и не доказанная доходность стратегии.
- Процентили индикаторов рассчитываются по **доступной истории каждого ряда**. Это особенно важно для ограниченной истории некоторых спредов ICE на FRED.
- Исторический график **пересчитывается по текущим пересмотренным значениям статистики**; лаги выхода отчётов оценочные, **не** реальные исторические винтажи и **не** корректный бэктест торговой стратегии.
- Источники могут быть недоступны или пересматривать данные. Внутренний контроль доступности/свежести — не независимый аудит информации.
- Простые пороги Risk-off и «системного стресса» объяснимы и единообразны, но **не имеют доказанной статистической калибровки**. Следует проверять исходные значения и даты перед решениями о деньгах.
- «Данные на сегодня» означает последнее доступное наблюдение каждого показателя, а не то, что все показатели опубликованы сегодня.

Ни один JSON с искусственными тестовыми значениями **не входит в архив**: настоящие файлы `data/*.json` создаются только после штатного workflow.
