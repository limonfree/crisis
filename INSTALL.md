# Установка аварийного исправления Crisis Engine v4.2

1. **Скачайте ZIP и загрузите содержимое в корень репозитория** `limonfree/crisis`. В корне должны оказаться `index.html`, `engine.py`, `collect.py`, `v4.py`, `evaluate.py`, `freshness.py`, `market_watch.py`, `README.md`; workflows — строго в `.github/workflows/`; тесты — в `tests/`.
2. **Не удаляйте `data/`**: существующие ежедневные архивы и кэш остаются на месте. Создавать вручную JSON с придуманными значениями нельзя.
3. Откройте GitHub **Actions → update-data → Run workflow**. После запуска проверьте лог выбора VIX `VIX chosen: ...`, а затем `HEALTH ... expected: ... blockers: []`.
4. Затем откройте **Actions → market-watch → Run workflow**. Проверьте новый JSON `data/market_watch.json`. Автоматические проверки запланированы: каждые 30 минут круглосуточно; дополнительно в 13:15, 13:45 ... 23:45 UTC по будним дням.
5. Проверьте на сайте `data/health.json` (ключ `critical_ready: true`), `data/latest.json` (`source_health.critical_ready: true`) и `data/market_watch.json` (даты, тип котировки, `status`). **Если критический источник отсутствует, интерфейс обязан показывать красное предупреждение и скрыть старый вердикт за раскрывающимся архивным блоком.**
6. Сверяйте дату наблюдения VIX с [Cboe](https://www.cboe.com/tradable_products/vix/vix_historical_data) и [Yahoo ^VIX](https://finance.yahoo.com/quote/%5EVIX/history/). Старый FRED VIXCLS может легально публиковаться на следующий день.

### Что означают состояния

- `health.status=ok`: все проверяемые ежедневные ряды поступили за последнюю закрытую сессию.
- `health.status=warning`: VIX и S&P достаточно свежие, но часть других ежедневных рядов (например, HY/CCC) отстают. Включите осмотр конкретных дат.
- `health.status=critical` или нет файла: состояние рынка по общей модели **не подтверждено**; старые сигналы не используются как текущие.
- `market_watch.status=ok`: котировки подтверждены по времени, но могут быть **последним закрытием**, а не интрадей.
- `market_watch.status=partial`: во время торгов часть внутридневных котировок не получена; используются данные предыдущего закрытия с соответствующей подписью.
- `market_watch.status=unavailable`: недостоверная или недоступная свежая котировка, интерфейс показывает предупреждение.

### Проверки до публикации

`python -m unittest discover -s tests -v`

Тесты используют искусственные сценарии для проверки граничных дат, исключения незавершённых свечей и отказобезопасности, **не являются сетевым испытанием GitHub Actions**. После установки обязательна независимая сверка живых опубликованных JSON и успешного запуска обоих workflow. GitHub Pages сам не умеет запускать Python и кнопка «Обновить» лишь перечитывает опубликованные JSON.
